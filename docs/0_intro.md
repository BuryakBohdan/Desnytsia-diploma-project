# ВСТУП

## 1. Актуальність теми
Сучасні мобільні операційні системи Android активно використовуються користувачами з низьким рівнем цифрової грамотності, які потребують оперативного стороннього адміністрування та технічної підтримки. Наявні комерційні рішення вимагають складного ручного конфігурування та мають високі системні вимоги. Ключовою інженерною проблемою є забезпечення стабільного, низьколатентного (Low Latency) P2P-з'єднання в умовах нестабільного інтернет-трафіку або повної втрати зв'язку, а також мінімізація ручних дій з боку кінцевого користувача. Розробка спеціалізованої розподіленої системи «Десниця» дозволяє вирішити цю задачу шляхом поєднання протоколу WebRTC та автоматизованих зашифрованих SMS-тригерів для відновлення з'єднання.

## 2. Об'єкт дослідження
Процес віддаленого адміністрування, управління інтерфейсом та передавання потокових мультимедійних даних у розподілених мольних середовищах Android.

## 3. Предмет дослідження
Методи, архітектурні патерни та технології (Kotlin, Jetpack Compose, WebRTC, Accessibility API, WebSockets та зашифровані SMS-тригери), спрямовані на оптимізацію затримок, забезпечення відмовостійкості та безпеки віддаленого керування пристроями.

## 4. Мета роботи
Проєктування та розробка кросплатформної розподіленої системи «Десниця» для забезпечення віддаленого адміністрування Android-пристроїв із мінімальною латентністю візуального потоку та наявністю аварійного каналу відновлення зв'язку.

## 5. Завдання проєкту
1. Проаналізувати існуючі аналоги та рішення для віддаленого адміністрування мобільних пристроїв за вимогами ДСТУ.
2. Обґрунтувати вибір технологічного стека та спроєктувати архітектурні патерни (Clean Architecture, Event-Driven Architecture).
3. Спроєктувати архітектуру системи за допомогою моделей UML та C4 (Component, Container diagrams).
4. Здійснити алгоритмізацію критичних вузлів (сигналізування через WebSockets та захоплення екрана через MediaProjection API).
5. Проєктувати користувацький інтерфейс та інтегрувати спеціальні системні служби Android (Accessibility API).
6. Провести інструментальний аудит коду, тестування надійності та оптимізацію мережевих затримок (Latency).
7. Здійснити розгортання прототипу, апробацію рішень та підготувати технічну документацію.
