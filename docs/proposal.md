# Thesis Proposal: Розробка мобільного застосунку «Десниця» для віддаленого адміністрування та технічної підтримки Android-пристроїв
# Development of the "Desnytsia" Mobile Application for Remote Administration and Technical Support of Android Devices

## 1. Актуальність та проблематика
Сучасні мобільні операційні системи Android часто використовують користувачі з низьким рівнем цифрової грамотності (зокрема представники старшого покоління), які критично потребують оперативної сторонньої допомоги під час конфігурації пристроїв чи усунення програмних збоїв. Існуючі комерційні рішення для віддаленого керування (наприклад, TeamViewer або AnyDesk) вимагають складних ручних налаштувань, мають надлишковий інтерфейс або високі системні вимоги. 

Головною технічною проблемою є забезпечення стабільного та захищеного низьколатентного з'єднання в умовах нестабільного інтернет-зв'язку (або повної його втрати), а також мінімізація ручних дій з боку кінцевого користувача. Метою проєкту є створення спеціалізованої розподіленої системи «Десниця», що забезпечує автоматизоване віддалене адміністрування Android-пристроїв із резервним каналом керування через SMS-тригери.

## 2. Ідея продукту та архітектурний тип
Проєкт є кросплатформною кліент-серверною системою, що поєднує мобільний застосунок «Десниця» (клієнтська частина на Android) та високопродуктивний сигнальний сервер. Архітектура побудована за принципом подієво-керованої взаємодії (Event-Driven Architecture) із застосуванням P2P-протоколів для передавання аудіовізуальних даних у реальному часі та механізмів відмовостійкості рівня мережевого каналу.

## 3. Детальний опис функціоналу (Core Features)
1. **Трансляція екрана в реальному часі:** Захоплення кадрів інтерфейсу за допомогою системного API `MediaProjection` та передавання відеопотоку з мінімальною затримкою через протокол WebRTC (Video Track).
2. **Віддалене керування інтерфейсом:** Програмна імітація жестів (натискань та свайпів) за допомогою спеціалізованих системних служб Android (`Accessibility API`).
3. **Сигналювання та управління сесіями:** Розробка виділеного Signaling Server (Node.js / Ktor) із використанням протоколу WebSockets для ініціалізації та маршрутизації P2P-з'єднань.
4. **Канал обміну даними (Data Channel):** Передавання керуючих команд, системних логів та статусів з'єднання через WebRTC Data Channel із забезпеченням низьких накладних витрат.
5. **Аварійне відновлення зв'язку через SMS:** Автоматизований моніторинг стану мережі (Wi-Fi / Mobile Data) та перехоплення вхідних повідомлень за допомогою `BroadcastReceiver` для виконання зашифрованих команд відновлення з'єднання у разі втрати інтернет-доступу.
6. **Модуль аутентифікації та безпеки:** Шифрування керуючих команд і сеансів зв'язку для запобігання несанкціонованому перехопленню керування пристроєм.

## 4. Попередній технологічний стек
* **Мови програмування:** Kotlin, TypeScript / JavaScript (або Kotlin для серверної частини).
* **Мобільний фреймворк:** Jetpack Compose, Android SDK.
* **Архітектурні патерни:** Clean Architecture, MVVM, Event-Driven Architecture.
* **Мережеві протоколи та технології:** WebRTC (Video Track + Data Channel), WebSockets, TCP/UDP.
* **Системні API Android:** MediaProjection API, Accessibility API, BroadcastReceiver.
* **Серверна частина:** Node.js або Ktor (Signaling Server).
* **Інструменти розробки та DevOps:** Git, Docker, Gradle, GitHub Actions.
